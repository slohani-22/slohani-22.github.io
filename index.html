AWSIdentity & access

“Six months later I audited my own access system. A grant meant to last 5 minutes was still active.”

SecureCorp AWS IAM Lab

  1. 01

    The goal

    Run identity for a made-up four-department company: who can sign in, what each team can touch, and how someone gets temporary extra access.

  2. 02

    What I built

    Single sign-on from Entra ID to AWS, keyless GitHub deployments with OIDC, group-based roles with MFA and permission boundaries, and a request-and-approve flow for temporary access, all automated with Lambda.

  3. 03

    What I found

    The step that removes access never ran. The audit log still said "approved," so everything looked fine. Lesson: check what's actually attached, not what the function reported.

AzureDetection & response

“I attacked my own Azure environment in eight stages, then wrote the detections to catch it.”

Microsoft Sentinel SIEM Lab

  1. 01

    The goal

    Build a working security operations setup on Azure and prove the detections fire on real attack activity, not sample data.

  2. 02

    What I built

    Detection rules mapped to MITRE ATT&CK, written investigations, and a playbook that disables a compromised account automatically through Microsoft Graph.

  3. 03

    What I found

    Some rules fired on normal admin work and needed tuning. My new-account rule never fired at all, because the attack script ran as SYSTEM, which doesn't log those events the way a real sign-in does.
